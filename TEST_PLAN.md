# Test plan

Every acceptance criterion (AC) has (a) a **full run** that produces an
evidence file `acceptance/results/acN.json` and (b) a **smoke run** that
`scripts/status.sh` executes every time. Evidence records the git tree hash
of the source it ran against (`git rev-parse HEAD:crates`, `HEAD:bridge`,
`HEAD:Cargo.lock`, combined into `source_fingerprint`). `status.sh` reports
an AC as:

* `PASS`  — evidence exists, `pass == true`, its parameters meet the full
  thresholds below, its fingerprint equals the current tree, **and** the
  smoke run passes now;
* `STALE` — evidence passes but was produced on different source;
* `FAIL`  — smoke fails or evidence says fail / missing.

Full runs: `scripts/acceptance.sh acN` (writes the evidence file).

## Unit / component suites (always run by status.sh)
| suite | command | covers |
|---|---|---|
| interfaces | `cargo test -p interfaces` | fixed-point parse/format/rounding |
| hlwire | `cargo test -p hlwire` | msgpack byte-equality vs vectors generated by the Python SDK and TS SDK; L1 & user-signed signature recovery vs SDK-signed vectors |
| book | `cargo test -p book` | price-time priority, partial fills, IOC/ALO/GTC, cancel, levels; proptest vs naive reference book |
| clearinghouse | `cargo test -p clearinghouse` | margin, leverage, isolated, fees, funding, liquidation, insurance, ADL; **proptests for AC4 invariants** |
| oracle | `cargo test -p oracle` | weighted median, staleness, skew resistance (< 1/3 stake cannot move median outside honest range) |
| state | `cargo test -p state` | action semantics (HL behaviors), nonces, agents, triggers, TP/SL, scheduled cancel, bridge accounting, root determinism, snapshot/restore |
| consensus | `cargo test -p consensus` | in-process simulated network: safety under partitions/drop/reorder/crash/equivocation (proptest over seeds), liveness after heal, state sync |
| net, mempool | `cargo test -p net -p mempool` | framing, handshake auth, reconnect, chaos shim; dedup, rate limits, reap order |
| api | `cargo test -p api` | JSON shapes of every /info and /exchange response vs recorded HL examples; WS protocol |
| relayer | `cargo test -p relayer` | ABI encoding, EIP-712 withdrawal digest equals Solidity's |
| sim | `cargo test -p sim` | generator determinism (same seed => identical log bytes) |
| bridge | `forge test` in `bridge/` | deposits, withdrawals, **replay protection, signature threshold, validator set rotation** |
| no-float | `scripts/check_no_float.sh` | no f32/f64 tokens in state-machine crates |

## AC1 — Consensus safety under faults
* Config: 7 validators (equal stake, f = 2), real `hlnode` processes, chaos
  controlled via `/admin/chaos`, load from `sim load` at a modest rate so
  blocks carry txs.
* `hlchaos run --validators 7 --duration 12h --max-faulty 2 --seed S`
  loops fault episodes (random, seeded): kill -9 + restart (≤ 2 nodes),
  partitions (minority/majority splits, isolating ≤ 2 nodes, plus full splits
  that halt progress e.g. 3|4 and 2|2|3), per-link delay 0–2000 ms,
  drop 0–30 %, reordering; each episode 20–120 s followed by a heal.
  At most 2 validators are "faulty" (killed or isolated/lossy) at any time,
  except for whole-network splits used to test resumption.
* Safety checker: every node appends `(height, block_id, exec_root)` on
  commit to `commits.log`; checker asserts for every height all nodes that
  committed it agree on block_id and on exec_root for every executed height
  (also verifies QCs in committed.log). Any `STATE DIVERGENCE` or conflicting
  commit = violation.
* Liveness: after each heal, measure time until the max committed height
  across nodes increases by ≥ 2 blocks; must be ≤ 10 s for every heal.
* Evidence: `{duration_s ≥ 43200, validators: 7, episodes, heals,
  max_resume_ms ≤ 10000, safety_violations: 0, pass}`.
* Smoke: same harness, 3 minutes.

## AC2 — Determinism
* `sim gen --seed 42 --actions 50000000 --sim-days 7` -> `week.log.zst`
  (block log with real signed txs; block interval 6 s sim time => 100,800 blocks).
* Replay A and replay B: 4 `hlnode` validators in `--replay-log` mode over
  real consensus; each writes `roots.log`. Pass iff for every height all 4
  validators' roots are equal within a run, and run A == run B at every
  height, and the final height equals the log length. Also the offline
  `sim replay` roots must equal the network roots.
* Evidence: `{actions ≥ 50_000_000, sim_days ≥ 7, blocks, validators: 4,
  runs: 2, mismatches: 0, roots_digest, pass}`.
* Smoke: 200k actions, 1 sim-day, 2 runs, 4 validators.

## AC3 — Throughput
* 4-validator benchmark config (`scripts/localnet.sh bench`), release build.
* `sim load --mode bench` pre-signs order traffic (market makers placing /
  cancelling / modifying in batches of 50 per signed action, takers IOC) and
  submits through `/exchange` across all 4 nodes; measures committed order
  actions per second from `BlockOutcome.order_actions` over a 120 s steady
  window (after 20 s warmup), and block-time median from committed headers.
* Pass: sustained ≥ 100,000 order actions/s averaged over the window, no
  10 s sub-window below 90,000, and median block time < 1000 ms.
* Evidence: `{validators: 4, window_s ≥ 120, actions_per_s, min_10s_window,
  median_block_ms, pass}`. Smoke: 20 s window at 10,000 actions/s.

## AC4 — Clearinghouse invariants
* Property tests (`cargo test -p clearinghouse -p state`): random sequences
  of deposits/withdrawals/transfers/orders/price moves/funding/liquidations;
  after every step: conservation exact, funding nets to zero (incl. dust),
  after each liquidation pass no negative equity unless BadDebtCovered.
* Replay: `sim replay` checks `check_invariants` **every block** of the AC2
  week log (the node also runs them every block in `--replay-log` mode).
* Evidence: `{proptest_cases, replay_blocks_checked, violations: 0, pass}`.

## AC5 — SDK compatibility
* Start `scripts/localnet.sh dev` (4 validators, API on 3001..3004; genesis
  funds the example accounts).
* Python: official `hyperliquid-python-sdk` (pinned commit) installed from
  the clone; examples copied verbatim, only `constants.TESTNET_API_URL`
  occurrences replaced with `http://127.0.0.1:3001` by
  `acceptance/sdk/run_python.sh` (sed; diff printed and checked to only
  touch the URL). Scripts in scope (order placement, cancels, leverage,
  transfers, WS): basic_order, basic_order_with_cloid, basic_order_modify,
  basic_market_order, basic_tpsl, basic_adding, basic_leverage_adjustment,
  basic_transfer, basic_spot_transfer (PURR balance transfer; spot tokens supported for balances/transfers only), basic_spot_to_perp,
  basic_withdraw, basic_agent, basic_schedule_cancel, cancel_open_orders,
  basic_ws. Pass = exit code 0 (long-running WS examples: runs ≥ 30 s,
  receives at least one message on every subscribed channel, then is
  stopped) and no `"status": "err"` in output **except** entries in the
  expected-error allowlist `acceptance/sdk/expected_errors.json`, each of
  which must name the call, the exact error text, and why real HL returns an
  error in that situation too (D23). The runner fails if an allowlisted error
  does *not* occur (so the list cannot hide drift).
* TypeScript: `@nktkas/hyperliquid` (pinned npm version): README examples
  saved as scripts in `acceptance/sdk/ts/` (verbatim except transport URL),
  covering order, cancel, modify, updateLeverage, usdSend, withdraw3,
  subscriptions (allMids, l2Book, userFills, orderUpdates), run with node.
* Evidence: per-script pass/fail list, `pass` iff all pass.

## AC6 — Bridge
* Foundry suite (`forge test`): must include tests named
  `test_ReplayProtection*`, `test_SignatureThreshold*`,
  `test_ValidatorSetRotation*` (status.sh asserts presence and pass).
* E2E (`acceptance/bridge_e2e.sh`): anvil + deploy + 4-validator localnet +
  watchers + relayer; user approves & deposits 1000 USDC on Anvil ->
  balance appears in `clearinghouseState` -> trades (Python SDK order fill
  against a resting MM order) -> `withdraw3` 500 -> relayer submits ->
  Anvil USDC balance increases by 499 (fee 1). Evidence records tx hashes and
  balances.
